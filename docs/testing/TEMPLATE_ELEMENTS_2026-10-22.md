# 原图元素替换重做与验收

旧扩库实际使用 `reaction-story-v1 / make_story`：保留完整原表情，另加照片区、配文区，且导出器默认填入“看到这张图时的我”。这没有完成原图头像或原字替换。仓库 skill 还把这种拼接写成扩库默认路线，导致错误重复发生。

本次将默认流程改为逐张理解、逐帧标注的原图元素替换。参考自带的 `petpet`、`kiss`、`throw_gif`、`hold_grudge`：固定背景和动作，先去除原五官或完整原字，再放入用户头像或文字，最后保留手、杯子、帽子、眼泪、红包等前景元素。文本模板不再要求没有用途的照片输入。

## 当前 skill 如何工作

仓库 `skills/meme-to-template` 与本机 `/Users/shangkun/.codex/skills/meme-to-template` 已同步。安装前版本保存在 `/Users/shangkun/.codex/skills-backups/meme-to-template-before-elements-20261022`。

1. 保存来源、哈希和原始尺寸，区分角色、五官、配文、动作、道具、特效、署名以及无法确认的元素。OCR 和跟踪器只生成提议。
2. 为每个解码帧写出头像范围、原五官移除多边形、前景遮挡洞、显隐、原字完整范围和排版、源帧索引与时长。
3. 离线预制局部清理图层、原字默认恢复图层及所需素材；生成有边界限制的 `TemplateSpec.frames`。运行时只执行本地声明式渲染，不再识字、跟踪或补画背景，也不执行模型生成的任意代码。
4. 用真实头像、透明头像、新短句、空文字检查实际替换；源图预览不算换脸成功。逐帧查看实际动效，再以精确配方哈希记录审阅结果。
5. 发布只接收通过审阅与执行检查的配方；无法可靠拆分的素材保留待处理。旧拼接导出器必须显式选择 context-story 且逐项提供文案，不能作为默认转换降级。

当前头像层替换面部，通常保留原头发、耳朵与轮廓；用户需要先框选上传照片中的脸。上传头像提供表情，本次没有实现表情迁移。复杂身体姿态与大角度三维转头仍需专用变换适配器。
