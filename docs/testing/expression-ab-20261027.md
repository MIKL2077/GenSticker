# 2026-10-27：模板库 A/B 表情融合实验

本次按用户要求修改当前全部带图模板，固定随机分配 A/B，并在原先保留的六张测试照片上测试预先抽定的 100 个模板。A/B 是实验性效果，算法执行、渲染完成、像素/时序检查均不代表人工视觉验收。

## 算法与接入

`expression_math.py` 的八个数值函数与此前实验脚本的 AST 完全相同。冻结脚本 SHA256：`6cf3e02a5912b4b1bbce11121f9780cf6a5043700e93947c49e6be94cf286314`。

A 使用 0.58 的表情强度，保留较多输入五官形状，必要时借用模板嘴内纹理。B 使用 0.94，保留相对稳定的输入面部并移植模板嘴部组件；牙齿/嘴唇等不一定来自上传照片。保留 `cpu-character-v1`、原贴图算法及无脸/模型不可用回退。

声明式模板将离线关键点、保护遮罩、源帧和修补底图保存在有界配方中，替换 face 层。原生 Python 模板先在上传照片的坐标内融合，再执行原有布局、道具、文字、动画及编码。纯文字模板不参与。没有可测量原表情的相框、举牌、图标等布局仍保留原算法，不把回退计为融合。

每个请求的每个输入槽只检测/分割一次，动画帧共享请求内结果；不持久缓存用户人脸。模板检测、修补与缺失帧几何插值全部离线完成。静态多人/远景图会对既有 face 槽裁剪后检测。缺失帧仅在同槽有可靠参考帧时，在槽的相对坐标中插值；这不是运行时检测或生成新表情。插值仍需人工评估。

原 GIF 源帧继续使用原来的压缩素材；修补底图存储为无损局部补丁。逐项检查重建后像素完全一致。融合最后只写允许区域，保留当前画布的固定像素和已经修改的文字/其他对象。GIF 共享调色板可能造成保护区编码色差，像素检查不等同于编码后零色差。

带 A/B 策略的模板强制走服务端，避免客户端旧配方绕过融合。原生启动恢复保留策略，刷新不会重复包装函数。模板/版本的素材回收和归档现在也保留 A/B 的三个依赖素材。

## 分配与版本

随机种子是 `GenSticker-expression-AB-20261027-v1`。482 个带图模板分为 A/B 各 241 个，稳定 key/UUID 不变，版本各加一；476 个纯文字模板不变。100 个测试模板先于检测与渲染抽定，各模式 50 个，没有按输出效果重新抽样。输入包括眼镜、墨镜、笑脸、正面及侧面等六张已有测试照片。

发布快照中已有审核证据描述的是原模板。新增 `expression_policy.visual_status=pending-user-review` 明确标记新效果尚未视觉验收。不要用旧 `quality.spec_sha256` 认证新 A/B 效果。

`expression_batches` 是绑定原版本/指纹的当前库升级增量，独立于已审核源模板的导入批次，不把新来源自动批准。已更新/归档/撤下/被编辑的模板不会被旧增量覆盖；重复恢复不增加版本。它不是针对任意新库或未来所有新来源的自动配方检测器。

## 复现与部署

使用 `tools/qa/author_expression_library.py` 读取公开模板快照并离线编译，再用 `finalize_expression_library.py` 补齐同槽时间线并压缩无损素材。`test_expression_library.py` 在隔离状态目录使用真正的 Meme 调用路径运行 100×6；`build_expression_gallery.py` 输出本机对比图库。测试原图、成品、包含个人照片的截图和完整私有报告不提交到 Git。

依赖仍为本地 CPU MediaPipe + OpenCV。面部模型 SHA256 为 `64184e229b263107bc2b804c6625db1341ff2bb731874b0bcc2fe6544e0bc9ff`；六类分割模型 SHA256 为 `c6748b1253a99067ef71f7e26ca71096cd449baefa8f101900ea23016507e0e0`；规范脸 OBJ SHA256 为 `8bac80443397e113f41a8b565ea72c59390bc031d9defab289dba7bc0c54e618`。模型下载只在部署/准备时进行，用户渲染不访问外部服务。

部署用 `deploy/package-expression-library.py` 生成公开素材与代码增量；`apply-expression-library.py` 核对旧文件散列、模板版本/指纹和空闲队列，保存原文件与数据库快照后更新，验证 482 个版本、分配和服务健康。失败回滚只恢复本次匹配的模板行与版本，不覆盖用户任务/账号/上传数据。备份路径记录于私有部署报告。

结果汇总与无个人照片的分配、抽样及作者验证记录保存在 `docs/testing/evidence/2026-10-27-expression-ab/`。具体统计以最终测试汇总为准。

最终本机测试：100 模板 × 6 照片，共 600 个结果（270 个 GIF、5490 帧），252 个实际融合、348 个回退，0 渲染失败；尺寸、时序和循环次数无异常。348 个回退结果与修改前像素相同，252 个融合结果均有实际像素变化。174 项回归测试通过。240 个融合案例有三角形折叠诊断记录，B 的身份保持及侧脸、动漫脸的破边问题仍需人工挑选。

九宫格的两个渲染线程在请求内共享一次照片分析；原生路径的共享上下文会在调用结束后释放。部署时统一公开代码、配方及素材的可读权限，并在启动前使用实际服务账号打开所有依赖素材和两个模型。
