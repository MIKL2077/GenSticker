# MiniMax 自动发布与分享封面验收（2026-10-26）

现有服务器已开启合格模板自动发布。此前 2026-10-23 的“仅采集、不发布”记录是历史状态，不代表本次上线状态。相关机器私有配置和验收原始文件不提交 Git。

## 发布规则与执行状态

每六小时按原定时器运行来源发现、去重、MiniMax skill 拆解、本地真实渲染及视觉复核。只对公共素材进行离线制作，不把用户上传照片交给 MiniMax。现网使用 Mainland Token Plan 的 MiniMax-M3，以及另一次独立调用的 Token Plan 图像理解接口；这不代表跨厂商独立审核。

发布入口新增强制复核：

- 逐帧主审核的所有必需标志为真，分数至少 85，逐帧无未解决缺陷；审核帧号完整且不重复，分数与模板证据相同。
- skill 文件 SHA256 与当前运行版本一致；原图的照片槽、完整原文案与最终输入一致；模板 spec 哈希、帧数和受保护像素检查通过。
- 每一帧、每个照片槽都有本地人脸位置及覆盖证据；未知卡通、遮挡、覆盖不足仍需后续处理，不能仅凭模型分数放行。
- 每一帧通过另一次图像接口复核，包括旧脸移除、文案完整和道具保留。
- 素材哈希、来源署名、去重、总空间和在线模板上限均通过。主审核完整结果和发布策略版本随模板版本入库，发布与新模板批次成员关系在同一事务提交。

目标仍默认每轮 5 个，可配置 3–10 个。达到目标记 `completed`，有合格项但不足目标记 `partial`，零个合格记 `attention`。不合格项不上线。已完成时段重复启动返回原报告，避免不断消耗模型额度；运行中断仍可按原机制恢复，主动重试须显式 `--force`。现有调用、下载、存储预算和 8000 在线模板上限保持生效。

本次验收指定两张此前私有样本使用的公共原图，由当前 MiniMax 重新生成，经过当前全套生产发布函数，不导入旧成品，也不走人工绕过审核的发布接口：

- `auto_305e9ed41fc696643bf69eb3`：我就是这么强大。
- `auto_fe3c93637403bf05ce67a6e3`：全都一起上吧。

两张本次主审核均为 98 分，并通过本地几何及逐帧图像复核。再次人工查看五列对照：原图、实际头像替换、清空文案、修改文案、透明主体输入；原脸与原文字按槽替换，保留发型、身体、动作、手势和画布结构，与上一批通过验收的原位置替换方式一致。此结论针对已检验样本，不能推断任意复杂遮挡／多行／GIF 都达到同等效果；不满足检查的候选会保持 pending。

两张已实际发布，在线模板由 944 增至 946。本次只提供了两张候选，因此报告如实记 `partial`，不代表验证了每轮都能新增至少三张。新模板试用接口已返回其中一张，微信开发者工具使用真实服务完成生成，并验证使用后立即隐藏、重开页面仍隐藏。自动发布开关私有文件权限为 root:root 0600，API、worker 和六小时 timer 均 active。上线前保存了代码备份和原开关配置；关闭新发布可将私有开关设回 0，已有模板仍可使用。
