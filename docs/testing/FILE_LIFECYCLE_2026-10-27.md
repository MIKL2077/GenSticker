# 临时文件登记与回收（2026-10-27）

## 修改范围

保持模板、搜索、GIF 预览、融合参数、编辑操作、生成队列、保存和分享的业务行为不变。此次只调整前端文件生命周期，后端接口和渲染逻辑没有修改。

原实现只在内存中登记文件。重新编译或冷启动后，匿名下载与画布导出文件失去回收依据；首页缩略图复制到持久缓存后，原下载文件也没有及时释放。

## 回收规则

- 新增 `gensticker.files.v1`，仅保存明确由应用创建或下载的本地文件路径、用途和时间，不保存图片内容。
- 编辑导出、抠图蒙版、压缩副本、下载结果、拼图、客户端渲染、模型下载中间文件及本地作品均接入登记。缩略图复制完成后立即释放原下载文件；模型下载中间文件在保存成功或失败时释放，已缓存的模型权重保留。
- 当前会话中的临时文件保持保护，生产者确定用完时释放。未正常释放的文件可在下一次启动时回收；删除失败保留登记，之后重试。
- 在每次删除前检查正在编辑的文件、读者引用、当前显示的缓存，以及所有账号和游客七天内的本地作品、编辑副本和 Live 源文件。读取保护索引失败时暂停删除。
- 旧版已有的应用命名文件、公开预览索引和本地作品引用纳入迁移。未被引用的临时导出保留一分钟缓冲期。公开缓存继续使用原有容量预算；空闲回收可以被用户操作打断。
- 空间不足时回收可释放文件并重试一次；仍失败时保留原始 SDK 异常和错误码，写入控制台。权限错误不再仅因为包含 `storage` 就被误判为配额不足。

历史 `tmp` 目录中的随机文件无法一概认定为应用垃圾，其中可能包含相册原图和运行时文件。因此没有批量清空此前发现的 8952 个匿名文件。此限制用于避免误删，不影响新文件的持续登记和回收。

## 验证

37 项前端回归脚本通过，覆盖模板缓存、搜索、GIF、编辑、生成、队列、分享、视频、本地模型及账号隔离。新增场景验证跨启动登记、删除失败重试、并发可见性变化、前台操作中止清理、读者引用、各账号七天保留和原始 SDK 错误。

微信开发者工具使用独立的原生文件目录和私有、基于文件的键值存储适配器隔离测试数据；未清空用户的原始缓存或作品。实际 Canvas、文件接口和公网 HTTPS 请求保持真实：

- 去背景、透明度预览、撤销、旋转、还原通过；模拟首次蒙版写入配额失败后，清理并再次写入成功，两次写入调用。
- 强制回收期间正在编辑的透明 PNG 保留，透明度范围为 0～254。
- 首页实际生成按钮返回可变化的 14 帧 GIF，总时长 1400 ms。
- 使用新的测试项目上下文重新打开后，已登记且超过缓冲期的孤立文件被删除；未知原图、已完成作品、重做源图和持久 GIF 缓存均保留。
- 微信构建与包体检查通过，构建包 864,476 字节，图片/音频 199,585 字节，没有新增媒体素材或依赖。

## 使用

重新编译 `frontend/dist/build/mp-weixin` 即可在开发者工具使用。体验版和正式版需要上传新版小程序才能启用新的文件登记逻辑。
