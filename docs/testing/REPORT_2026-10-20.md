# GenSticker 测试与交付报告

日期：2026-10-20（北京时间）。应用基线提交：`ece93f8`；测试工具、报告与文档为本次新增工作。目标平台：**微信小程序**。

结论：主要功能链路可以在开发验收环境运行，测试工具和文档具备交接条件；**公开上线验收尚未完成**。模板参数契约、导出体积、OCR 可用性、存储预算、数据删除、依赖升级和真机验证仍需处理。此公开报告经过脱敏，包含实际主机安全状态的完整报告通过私下交接。

## 一、执行范围与可信程度

本轮执行了前端服务检查、后端隔离测试、微信 production 构建、真实微信开发者工具、内置模板逐个渲染、真实模型／worker／FFmpeg 小样本、公开 HTTPS 读取、依赖公告查询及代码检查。

- 开发工作机的模板时间不能当作服务器时间。
- 源站接口时间不能当作微信手机端等待时间。
- 模拟的微信认证／审核结果不能当作真实平台批准。
- 两个样本的中位数和最大值只是观察，不构成稳定 P95 或容量承诺。
- 未进行最大并发、长期稳定性、整机故障、完整灾难恢复或实体手机测试。

详尽的用例、建议目标和未执行的人工项目见 [测试方案](TEST_PLAN.md)。

## 四、内置模板逐个测试

[原始 295 项](evidence/2026-10-20/catalog-smoke.json) · [七个失败归因复测](evidence/2026-10-20/catalog-followup.json)

使用合成头像、模板默认参数和声明允许的最少图片／文字，在本地逐个调用渲染器并解码成品：

- 295 个内置模板中，287 个按声明最少输入成功。
- 七个模板最少输入报“文本或用户名数量不足”；补充可选文字后全部成功：`alipay`、`always_like`、`ask`、`google_captcha`、`make_friend`、`wechat_pay`、`why_have_hands`。
- 一个 `dianzhongdian` 因未配置翻译服务失败；当前部署示例已将其停用，不把它计为已修复。
- 这意味着 294 个渲染器可用的样例，不等于 295 个最少输入用例全部通过。七个契约问题仍需要修改前端提示或模板输入约束。

本地内置集合与线上目录不是同一个集合：线上停用了一个内置项，并含用户种子模板。因此两个“295”不能拿来冒充线上所有已发布版本都完成了全面效果测试。

287 个最少输入成功结果中，118 个为多帧动画；其中 45 个大于 500 KiB、28 个大于 1 MiB。最大样例为 `kirby_hammer`，约 3.84 MB；本地最慢样例 `repeat` 约 4.10 s。没有对每个模板的所有参数、图片组合、帧内容和审美效果做穷举或人工观看。

建议提供“原版下载”和“微信适配导出”，并在真实微信入口验证，不将接口返回图片等同于可以直接添加为表情。

## 五、真实链路与功能效果

[脱敏核心与扩展样本](evidence/2026-10-20/performance-samples.json)

执行使用独立合成账号，测试完成后清理账号、私有持久素材与任务。不公开测试模板，不修改真实用户记录；少量实际生成统计可能计入热度。服务短期内存缓存按既有 TTL 过期。

### F01／F02／F11：浏览、账号、收藏和历史

真实分类／热度读取、资料更新、收藏／取消、历史、游客库合并、不同账号数据隔离通过。无会话访问私有接口为 401，陌生账号获取其他人的私有资源被拒绝。

扩展样本中的资料更新约 7.8 ms，库合并约 9.2 ms；收藏 PUT／DELETE 两次中位数约 10.4 ms。它们都是源站的小样本，不包含真实微信登录过程。

### F03／F04：静态、动画和编辑输入

真实生成 `always` 静态图和 `petpet` GIF，成品可解码，GIF 为多帧。首次生成与缓存命中分开记录。真实去背景预览返回透明 PNG，约 0.366 s，输出 267×421、约 13 KB。

裁剪／旋转／翻转、撤销、取消和迟到响应由前端及后端检查覆盖；没有据此声称手机上的所有手势和每张照片边缘都已人工验收。

### F05／F06：候选、九张、换批和动画

真实双人样例检测到两个候选，选择第二个区域后提交。核心基线连续两批各九张、相邻批次 key 无重复；结果中分别有三张、两张动画。用户确认的区域保持 `user-selection`，没有重新换脸。陌生账号读取完整结果被拒绝。

扩展复测又完成两批，实际选择反馈及关闭个性化通过，反馈接口约 10.1 ms，关闭偏好约 11.7 ms。没有在这两个样例上估算总体人脸、动物检测准确率。

### F07／F08／F12：视频、GIF 同步和队列

两个 9 秒样例经裁剪、90° 旋转、翻转和字幕处理后，均得到 240×180 GIF，45 帧、9000 ms，大小分别为 313,056 和 378,076 字节。全时长和 500 KiB 限制通过，平均约 5 fps；流畅度仍需真机观看。

本机成品同步的接口重试复用同一任务；不同账号不可取走结果。私有模板排队生成、标记查看、重做、删除已完成任务及随后读取为 404 通过。重做等待约 0.920 s。后台进程中断／过期恢复由隔离测试覆盖，没有为测试故意重启生产 worker。

本机 GIF 编码、超时回退、账号切换、退出页面后保留任务由前端检查覆盖；真实手机解码能力与系统杀进程行为仍待测试。

### F09：私有创作与发布边界

实际创建私有模板、预览和排队制作通过，私有背景的公共素材地址返回 404。创建模板 API 约 38 ms，创建制作任务 API 约 21.1 ms；这些创建响应不代表制作已经完成。

未勾选素材权利的 AI 制模请求被拒绝。文字／图片审核拒绝及外部错误由隔离测试覆盖。真实审核通过并进入公共仓库的正向路径未执行，避免发布测试垃圾内容。

### F10：真实 OCR 识图制模

[隔离 OCR 结果](evidence/2026-10-20/ocr-isolated.json)

真实 OCR 识别了合成图片的 `WHY NO?`，约 0.839 s，置信度约 0.896；低于当前 0.95 门槛，转换正确进入 `needs_manual`。它证明真实识别和保守回退运行，不证明成功产生了可编辑模板。

后端隔离测试中较高置信度的模拟识别可完成真实修复、重建和替换。上线前应扩充样例、测试中文／英文和字体，评估阈值及人工校正；识别失败仍消耗当日机会也需要改善。

### F13：采集、来源和质量

许可、来源白名单、重复检测、保护区、模糊／动画待处理、发布约束由后端检查覆盖；不宣称已连续验证所有外部来源可访问或成功获取全网热点。外部服务和长期定时运行另行观测。

## 六、性能结果和解释

测试机器为 4 vCPU／16 GB Linux，模型已预热；廉价读取最多两个并发，耗时任务串行。以下为核心基线：

- 健康读取 5 次，中位数约 1.5 ms，最大 4.1 ms。
- 分类读取 5 次，中位数约 30.7 ms，最大 34.3 ms。
- 热度读取 5 次，中位数约 3.7 ms，最大 4.1 ms。
- 两并发健康读取共 10 次，中位数约 1.7 ms，最大 3.1 ms；这不是最大吞吐测试。
- 静态 `always` 3 次，首次约 406 ms，重复缓存约 11 ms。
- 动画 `petpet` 3 次，首次约 38 ms，缓存约 11 ms。
- 九图核心两批分别约 1.64 s、4.43 s，包含轮询和完整结果下载；输出总字节约 0.463 MB、2.178 MB。
- 9 秒视频转换与取回约 3.10 s、3.41 s，准备素材另约 0.16 s。
- 扩展复测两批九图约 3.52 s、2.00 s，视频约 2.49 s、3.41 s。模板随机组合不同，不能将差异归因于单一优化。

[开发机公网样本](evidence/2026-10-20/public-network.json) 中，健康请求三个样本约 0.59～3.57 s，分类请求约 5.18～7.74 s。分类 JSON 解压后约 162 KB，实际 gzip 响应体约 24 KB。源站快速而跨网等待较长，下一步需要定位网络路径、Tunnel、预连接、缓存与真实运营商链路，不能仅据这些数据增加 CPU。

没有足够样本推算并发容量、DAU 或稳定 P95。也没有重启线上模型制造冷启动；冷启动、真实移动网络、低端手机和长时间稳定性仍待测。

## 七、安全和资源结论

[安全说明](../../SECURITY.md) · [修改优先级](../ROADMAP.md)

应用层本轮观察：私有读取隔离、私有背景保护、输入大小／时长限制、版权确认、幂等和频率保护通过。网关六次空 code 请求返回三次 422、三次 429，没有向微信发起有效登录。

锁文件非 dev 图的 npm 官方批量公告匹配为 21 个包／56 条，全图为 35 个包／89 条。其数量与 `npm audit` 的间接修复统计不是同一口径，也不等于小程序运行时实际可达漏洞数；需要逐项分析。

当前依赖声明、安全部署、存储预算和删除流程仍有上线阻断，详见安全说明。主机完整性、同机其他服务和实际云账期属于私下部署审计范围，不在公开报告发布具体状态。本报告没有执行漏洞利用，也没有证明没有漏洞。
