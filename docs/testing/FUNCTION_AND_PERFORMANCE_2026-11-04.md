## 逐项功能与待优化点

编号沿用 [测试计划 F01—F14](TEST_PLAN.md)。以下“隔离通过”指临时数据库、受控素材及必要的外部服务替身；并非已在真实账号执行发布、注销或发送图片。

### F01 首页、分类、搜索、人气与分页

- 已验证：真实目录加载、七页导航；中文、奶龙、主内、ASCII、同义词、组合与连写搜索；空结果、清空、分页重置及多行文字输入。搜索和分页逻辑的前端回归通过，人气／试用卡后端隔离回归通过。
- 待优化：目录接口本身较慢、首个分类可能等待缩略图；应提供有版本的目录快照，分类状态先更新，图片逐张加载，避免等待整批图片才呈现结果。
- 当前搜索没有测出需要立即重写的瓶颈；将来模板增多后再做预排序复用、组合词切分缓存和短延迟输入合并。

### F02 详情、示例分享、收藏与历史

- 已验证：真实详情与完整示例下载；GIF 为 24 帧、240×240、349,182 字节，PNG 为 521,251 字节。示例分享入口调用通过，原生分享菜单使用替身；收藏、历史、游客合并和账号隔离由前后端隔离测试覆盖。
- 待优化：首次详情等待约 1.64 秒，缓存打开约 23 ms。点击后应立即展开已有卡片资料与占位图，后续补齐详情；首屏详情可按用户意图预取，避免所有模板无差别预取。
- 待验收：iPhone／Android 实际发给好友、接收端 GIF 动画、取消分享、相册权限拒绝及保存。

### F03 手动套模板生成、静态图、GIF、多图与字符画

- 已验证：输入数量、文字、透明图与上传编码、客户端绘制、输出缓存、网络错误等回归；后端声明式模板、动画、生成限制及相关功能隔离测试通过。

### F04 图片编辑、裁剪、去背景、撤销与还原

- 已验证：微信真实画布／文件系统，透明公开 logo 作为选图替身；手动选区、翻转、旋转、透明通道去背景、撤销、还原、确认后提交均通过。不会未经确认把预览编辑当成正式输入。

## 实测：把等待时间与卡顿分开

### 微信开发者工具

正式构建基础库 3.17.5。以下是单次受控测量，带计时开销，没有统计显著性，也不是手机 FPS。

- 启动性能条目 `firstRender`：110 ms。只代表该性能 API 的渲染条目，未覆盖微信下载包、基础库启动及完整冷启动。
- 搜索七个关键词／清空：5—12 ms；翻页：10—12 ms；分类首次加载：1,245 ms，切回全部：10 ms。
- 首次打开详情：1,636 ms，缓存再次打开：23 ms；首次等待包含异步资料获取，不能据此认定逻辑线程冻结 1.6 秒。
- 小型公开 logo 翻转 43 ms、旋转 12 ms、上传编码 63 ms。没有测大照片；不能推广为 12 MP 照片的耗时。
- 交互探针的 16 ms 计时器：222 个样本，P95 间隔 21 ms，最大 41 ms；观察到的 19 次 `setData` 最大 JSON 长度 640 字符。字符数不等于 UTF-8 字节数；探针不能涵盖原生图片解码、真实触摸或所有组件通信。
- 独立示例测试的 50 ms 计时器：428 个样本，P95 52 ms、最大 100 ms；本机模型初始化 0 次。与上一探针不是同一个场景或采样频率。
- 本机 GIF 拼图约 2.75 秒，说明成品有等待；是否影响拖动／渲染必须在真机按帧确认。
- 构建目录检查：905,246 字节；其中媒体资源 199,585／204,800 字节预算。微信 CLI 另报上传 TOTAL 892,243 字节，两种统计口径不能混用。

探针计时从调用业务方法至其 Promise 返回及 Vue／微信 nextTick，**不保证所有图片已下载、所有帧已显示**。完整渲染与下载应另埋点，避免把快速返回冒充快速显示。

### 服务器小样本

在生产服务器本机通过回环 HTTP 串行读取，未压测，排除用户网络、TLS 和小程序端解析：

- `/healthz`：38 ms、200。
- `/memes/categories?compact=true` 三次：983／1,273／1,829 ms；每次 635,731 字节，1,010 个模板；响应没有 ETag 或 Cache-Control。
- `/recommend/catalog`：169 ms、200、112 字节。

精简目录约 620.8 KiB，且本机读取已近一到两秒，是需要优先验证和优化的路径。源码每次执行目录刷新、读取完整模板行、解析元数据、计算搜索词、排序和 JSON 序列化；这些是优化候选，尚未用 profiler 分配各项占比。开发机 Python 直连公网接口被返回 403，其时间不纳入成功延迟；微信实际下载与服务器回环成功，不能据此推断服务整体不可用。

## 按收益排序的实施建议

### 第一阶段：用户点击后立即响应，并建立真机基线

1. **首页与详情（P0）。** 后端缓存经过发布／撤回版本失效的目录快照，分离热度小数据，支持条件请求；客户端缓存优先展示，仅版本变化时重建索引。详情在点击时立即展开卡片已有信息和骨架，资料、预览分阶段补齐。分类不等待所有缩略图。验收包括撤回即时生效和账号隔离，不能让缓存绕过权限。
2. **GIF 与视频（P0）。** 服务端成品优先；记录本机回退原因及比例。本机保留时，将兼容的像素计算／GIF 编解码放入独立 Worker，并验证依赖、内存、数据传递和取消；无法可靠隔离的路径改服务器任务。只加 async 或每帧一次 setTimeout 不足以解决单帧同步阻塞。
3. **选图与编辑（P0）。** 手动框先可用、检测异步；预览限制分辨率；拖动合并更新，视图侧手势做平台验证；确认后再做高质量裁剪。旋转、去背景阶段保留可取消状态，禁止迟到结果覆盖新照片。
4. **同屏动画（P0 验证项）。** 测多张 GIF 同时播放造成的渲染／解码压力。只给可见且用户关注的少量卡片播放，其他显示静态海报；进入详情／离开页面暂停列表动画，完整分享文件仍保留动画。
5. **观测。** 分别记录点击响应、首个可见内容、下载、解码、处理、显示、队列等待、首张成品和整批完成；按机型、冷／热、网络、缓存命中分组。上传聚合耗时和错误码即可，不记录照片、Token、昵称和完整私有路径。

### 第二阶段：减少传输、重复计算和后台竞争

- 多图上传使用二进制文件和账号绑定素材 ID，避免重复 Base64／颜色蒙版复制；断网重试复用已完成上传。短期资产、删除、幂等及配额规则必须保留。
- 后端模型在服务启动后受控预热，健康状态区分进程存活与模型就绪；不要把大模型初始化放回页面、拖动或每个任务。
- 普通模板／选区／拼图等交互任务与九图、OCR、视频等长任务分队列，保留交互资源；先测 CPU、RSS 和峰值，不在共享服务器盲目增加并发。
- 统一活动任务轮询调度、请求去重和页面隐藏策略；弱网显示缓存与明确状态，缩短“无反馈等待”，提供取消和重试，而不是多轮长超时后才报错。
- 空间计费改增量账本，保留原子更新及定期全量核对；把非紧急磁盘清理安排到空闲时段，防止误删当前使用文件。

### 第三阶段：在测量结果支持时再调整包和框架

- 将视频／制模／重型编码依赖移入合适的分包并按用户意图预加载；主包当前不到 1 MiB，收益需通过冷启动实测验证。
- 更大目录再增加预排序／搜索缓存或服务端增量搜索，保留中文组合词及负向情绪语义测试。
- 升级 Pillow 与 uni-app 依赖栈，修复门禁后跑输出视觉回归和微信兼容验收。渲染架构迁移单独验证，不能当成流畅度的自动保证。

关于减少跨层通信、大图和高频数据更新的建议参考 [uni-app 官方性能说明](https://uniapp.dcloud.net.cn/tutorial/performance.html)。具体瓶颈判断来自本仓库与本轮测量；微信 Worker、WXS、分包改造均需按实际基础库能力实现并测试。

## 流畅度验收标准建议

这些是下一轮目标，不是本轮已经达到的结果。

- 定义参考设备：一台当前 iPhone、一台使用年限较长的 iPhone、一台中低端 Android；固定微信版本、系统和电量／温控状态。
- 点击后可见反馈 P95 ≤100 ms；60 Hz 设备拖动按约 16.7 ms 帧预算验收，120 Hz 设备单独制定目标。计时器间隔不能代替 FPS。
- 交互路径避免连续超过 50 ms 的 JS 阻塞；像素切块先以 4—8 ms 时间预算实验，并测原生解码、画布和桥接。
- 缓存首页可操作先以 P95 ≤300 ms、指定正常网络下冷启动可操作 ≤1.5 秒作为产品目标，后续按基线修订；冷启动定义包含哪些微信阶段需写清楚。
- 每个关键场景至少 20 次，分别记录冷／热、正常网／弱网、命中／未命中，报告 P50／P95／最大值；退出重进、切后台回来、连续制作、取消后重试都需要测。
- 长任务允许处理时间，但等待期间导航、取消、滚动和动画继续响应，用户可以离开并从队列恢复，不显示无法操作的整页遮罩。
- 单独记录 GIF／视频的质量、尺寸、时长和大小；性能提升不能以意外丢帧、截断时长、主体失真为代价。

当前 iPhone 镜像可以观察页面，但自动点击／滚动返回找不到可控制窗口，因此尚未完成上述实体手机验收。应使用最新预览包执行这些场景；线上旧包不包含本轮全部前端改动。

## 复现命令

在配置好依赖、已登录微信开发者工具的环境中运行。隔离回归不写生产账号；原生脚本使用受控公开／合成素材。

```sh
# 仓库根目录，使用已安装后端依赖的 Python
python tools/qa/run_local.py --build --output /tmp/gensticker-local.json

cd frontend
npm run build:mp-weixin
npm run test:mp-weixin -- --output-dir /tmp/gensticker-startup
npm run test:mp-weixin-template-features -- /tmp/gensticker-examples
node scripts/verify-template-editor.cjs /tmp/gensticker-editor
node scripts/verify-template-search.cjs /tmp/gensticker-search
npm run test:mp-weixin-queue-collage -- /tmp/gensticker-queue-collage
npm run test:mp-weixin-collage -- --output-dir /tmp/gensticker-result-collage
npm run test:mp-weixin-performance -- /tmp/gensticker-performance
```

原生检查逐个运行，避免多个开发者工具窗口和自动化端口相互干扰。计时脚本输出目录包含 `report.json`；如遇网络、工具或资料缺失，不应把失败改成跳过后宣称通过。
