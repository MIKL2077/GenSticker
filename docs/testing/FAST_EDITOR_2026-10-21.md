# 人物识别与去背景提速验收

日期：2026-10-21。范围：微信小程序模板图片编辑、AI 上传后的主体编辑；两处复用同一个 `SubjectPicker`。

## 最终行为

- 弹层打开即提供完整图片选框，读取图片尺寸后即可调整或确认，不等待网络识别。自动找到人物后默认选中最大候选；用户已经调整、切换、编辑或有保存的选框时，不覆盖其选择。
- 微信本机识别使用总计 900ms 的异步步骤预算。成功时不压缩上传图片；不支持或失败时进入服务器快速检测。服务器默认使用 28px 最小人脸，不在没检测到脸时自动运行分割；“精细识别”才查找小脸和前景主体。
- 识别只上传最长边 640px 的 JPEG。近期同一账号、图片路径和模式的检测结果在内存复用两分钟，最多十二项；不持久化照片。关闭或切换图片会中止旧检测，迟到结果不改变新编辑。
- 打开相册时提前准备本机模型；加载已有缓存与选人并行。选定范围稳定 250ms 后可提前在本机去背景，点击时直接复用结果；未就绪的模型最多短等 150ms，不等待首次下载再回退。预计算不会另行上传照片。
- 服务器检测可通过 `with_mask=true` 顺带为第一候选生成蒙版，复用已经收到的检测照片。只在额外处理槽空闲时计算一次，不排队；失败仍返回人物候选。手机仅在蒙版坐标等于当前选框时合成并缓存预览，点击去背景不需要第二次请求。
- 另行去背景时，上传最长边 640px 的小图，直接收到 320×320 透明蒙版，由设备合成原始照片像素，输出最长边 1280px；省掉完整 PNG 的额外下载。旧客户端的二进制和私有下载票据仍兼容。
- 已有透明通道的图片在本机直接复用；AI 后端收到用户确认的透明图片时不再次运行分割。翻转和旋转可与裁剪一次完成，避免重复解码与导出。

## 验证与实测

[回归记录](evidence/2026-10-21/fast-editor/regression.json)包含前端二十组检查、账号测试、后端功能测试及微信/H5 构建。新增覆盖快速检测不执行分割、显式精细识别、合并检测与蒙版、蒙版缓存与身份隔离、迟到检测不覆盖手动框选、预计算只运行一次、已有透明图不重复抠图。

[微信原生记录](evidence/2026-10-21/fast-editor/native.json)使用开发者工具原生 Canvas 和真实公网服务，验证：

- AI 编辑框和确认按钮不等待检测；模板入口同样可直接打开与确认。
- 实际双人脸检测连同第一候选蒙版约 10.12 秒，一次上传；同图再次读取检测结果约 0ms，无额外上传。
- 已返回的蒙版在原生画布合成约 44ms，保留透明通道，无额外上传或结果下载。该值仅指蒙版就绪后的合成，不能当作首次上传至完成的总时长。
- 已有透明图在本机复用约 20ms。

服务器独立进程对照：快速双人脸检测三次中位数约 299ms，遮挡人脸约 218ms，均未加载分割模型。与前一轮同机结果约 398ms、637ms 相比，默认快速检测恢复到旧版水平。单个人脸样本完整 PNG 约 173KB；蒙版 PNG 约 31KB，base64 约 41KB。样本和网络状态不同，不据此承诺所有用户耗时。

首次在微信工具中直接调用独立去背景仍观察到公网波动约 14～25 秒；合并返回蒙版用于避免用户点击后重复等待这条通路。选框改变、改选人物或预计算失败后仍可能需要独立处理。

## 部署与限制

后端 API 与 worker 已更新并通过健康检查；共享主机的其他服务健康。未提高现有 CPU、内存、流量或并发额度，蒙版接口沿用图片处理接纳和身份隔离。服务更新前检查运行文件、确认无活跃生成任务、备份修改模块；失败可恢复旧模块。

尚未正式发布微信小程序。开发者工具不能证明实体手机的 NPU、实际本机推理速度或微信版本兼容性；需要使用新版预览在 iPhone、Android 上验收。首次模型下载、复杂照片和公网弱网仍可能等待，不承诺所有操作瞬间完成。

建议真机测试首次选图、缓存后再次选图、多人切换、手动移动选框后去背景、连续关闭重开、翻转与撤销、已有透明 PNG，以及断网时使用已缓存模型。正常本机成功路径不上传照片；蒙版预览坐标不符时必须重新处理，不能误用另一个人的结果。

复现：运行 `.venv/bin/python tools/qa/run_local.py --build`；原生专项脚本为 `frontend/scripts/verify-fast-editor.cjs`，接收含 `qa-faces.jpg`、`qa-rotated.jpg`、`qa-alpha.png` 的公开/合成测试素材目录与输出目录。不要使用真实用户照片作为仓库测试素材。
