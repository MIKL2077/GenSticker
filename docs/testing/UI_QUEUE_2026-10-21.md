# 我的页面、队列与选人编辑调整

目标平台：微信小程序。日期：2026-10-21。应用提交 `e4405bb`，缩略图接口已部署。

## 变化

1. 浏览历史、收藏模板、管理素材与账号、隐私保护指引使用同一个卡片组件，统一白色圆角、图标底座、字体和阴影；去掉隐私入口前的系统表情符号。
2. 应用前台和“我的”页预取队列列表，短时间内合并重复请求。进入队列先显示账号自己的缓存记录，再后台更新；首次无缓存显示占位，网络失败保留旧记录。
3. 队列只下载 144 px 静态缩略图，按需展示前 20 条，滚动后继续加载；所有预加载共享最多 3 个下载。点击成品再取完整原图／GIF，保存和分享继续使用完整作品。缓存按账号和会话隔离，创建、查看、删除会更新缓存。
4. 选人和编辑使用一个弹层，保留候选人物、手动框选、翻转、旋转、去背景、撤销、还原和确认。编辑后可切换另一人，候选坐标仍来自原图；确认前不提交到外层。压缩图片区域，为工具和确认按钮留空间。普通推荐照片保持 JPEG，去背景结果保留透明 PNG。

## 已完成验证

- 20 组前端检查、97 项后端测试和微信／H5 构建通过，见[回归记录](evidence/2026-10-21/queue-ui/regression.json)。后续透明导出与弹层尺寸调整另行跑相关前端测试及微信构建。
- 缓存测试覆盖列表预取与进入时去重、慢缩略图不阻挡列表、全局三下载预算、缓存持久化、账号切换／同账号重新登录、旧响应拒绝回写。
- 选人测试覆盖明确选择、编辑预览后切换人物、撤销恢复、PNG 透明保留、确认后释放临时图和取消后的迟到结果处理。
- [线上小样本](evidence/2026-10-21/queue-ui/server.json)：静态原图 165,635 字节 → 缩略图 3,199 字节；五帧 GIF 原图 21,630 字节 → 缩略图 2,777 字节。缩略图首次源站约 11～19 ms，缓存约 9 ms；不是公网端到端性能或容量结论。原图帧数没有改变。
- 缩略图接口再次检查账号归属；陌生账号返回 404，删除任务后即使缓存存在也返回 404。测试账号已注销清理，没有发布测试内容。服务上线前核对旧代码哈希、有配置备份和失败自动回退，主页与 OpenClaw 健康检查正常。

[微信原生记录](evidence/2026-10-21/queue-ui/native.json)：卡片与缓存首屏通过观察，双人物弹层的两个候选框、三个工具与确认按钮均在视口内（[我的页面](evidence/2026-10-21/queue-ui/my.png)、[队列](evidence/2026-10-21/queue-ui/queue.png)、[合并弹层](evidence/2026-10-21/queue-ui/picker.png)）。缓存行在约 0.3～0.4 秒被自动化观察到，早于模拟的 8 秒列表响应；该时间包含 SDK 轮询，不是真机首绘指标。自动化工具跨自定义组件定位／XPath 出现超时，因此完整点击、翻转、再选另一人的原生自动检查明确记为待验收，未伪装通过；对应状态与图像处理已有前端行为测试。自动化使用合成账号和几何图形，不使用用户截图中的私人照片；模拟检测只检验选择交互，不代表真实模型准确率。

## 验收步骤

重新构建并导入 `frontend/dist/build/mp-weixin`：在“我的”检查两张新卡片；首次进入队列、返回再进、断网再进分别观察列表；点开 GIF 检查仍为完整动画，删除后返回不应重现。选一张多人照片，在同一弹层切换人物、编辑、撤销、再确认；在小屏设备检查工具和确认按钮。真机弱网、低内存与模型识别效果仍需人工验收，不能承诺首次无缓存时没有网络等待。
