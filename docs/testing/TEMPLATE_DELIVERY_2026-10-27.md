# 模板加载、搜索、动图与融合试验（2026-10-27）

本轮完成加载、搜索和动态预览；**语义五官融合没有通过用户验收，不作为完成项**。用户指出传统算法仍像人脸覆盖猫脸，随后认可保留原主体的方向，但要求用户五官更明显。普通入口不展示像素融合试验，后端、worker 和小程序的默认方式均恢复 `replace`。图片生成模型制作的对照属于离线方向验证，不是现有服务器的在线能力。

## 当前环境与可行性

已实际读取现有主机：4 vCPU、约 16 GB 内存、没有 NVIDIA GPU；GenSticker slice 共享预算为 200% CPU、MemoryMax 4 GiB。同机还有其他业务。现有 API 和 worker 可运行 Pillow / NumPy / OpenCV 的局部融合，不增加推理服务、第三方照片上传或付费调用。

调色和 [OpenCV seamlessClone](https://docs.opencv.org/4.x/df/da0/group__photo__clone.html) 能改善局部像素衔接，不能理解揉脸、惊讶、眯眼等表情，也不能可靠把人类五官转成猫咪的对应表情。`expression` 混合会保留更多原五官，但有重影或用户辨识度下降的风险。此次真实对照证实这些限制，不能宣称通过调色就实现语义融合。

需要进一步评估条件图片编辑模型、表情控制、逐帧一致性与身份保留，才可能达到用户目标。在当前 4 GiB 应用预算和无 GPU 环境下，尚未验证出可稳定在线运行的方案。CPU 也许能执行部分模型的低速离线推理，不能据此承诺小程序在线速度。增加 GPU 资源或接入图片编辑 API 涉及新的资源／服务选择，本轮未擅自启用。人脸生成模型也不能直接推断为适用于动物，例如 [InstantID](https://github.com/instantX-research/InstantID) 的代码、模型依赖和使用限制均需单独评估。

## 融合与模板修复的实际范围

- 新增 `face_blend` 的显式枚举：`replace`、`color`、`seamless`、`expression`。JSON、multipart、公开声明式模板和私有手工任务均保留参数，生成缓存也区分模式。
- 默认仍为 `replace`。只有从 `/pages/index/index?fusionLab=1` 进入，才显示“像素融合试验”及其限制说明；普通入口不展示。实验参数保留供可复现评估，不视为合格产品功能。
- 揉脸猫保留同一 key / UUID，模板版本从 2 升至 3。重做 14 帧内脸槽，保留头部轮廓、毛发、双手和动作标记；每帧都有保护区域。此修复解决遮挡问题，**没有解决将上传照片的表情迁移为原猫咪表情的问题**。
- 真实照片在服务器分别请求四个模式，均为 14 帧、1400 ms，请求总耗时约 2.45～2.74 秒，包含本次网络往返，不能当成主机纯推理时间或真机 SLA。
- 在有损 GIF 编码之前，14 帧 × 4 模式，共 56 次检查的固定区域像素最大偏差均为 0。GIF 调色量化后的像素可能有差别。
- 用户照片、对比图、请求体和离线图片生成示意仅在忽略的本地 `artifacts/`、`output/` 中，不上传 GitHub。模板批次只包含公共原图衍生资产和声明式配置。
- skill 的原位置编辑规范新增：表情依赖判断、逐帧保护手／爪／撞击符号，及“像素融合不能冒充表情迁移”的验收限制。自动发布的质量门槛不放宽。

## 首次进入与后续浏览

- 小程序使用 `GET /memes/categories?compact=true`，保留全部模板、分类、输入要求和搜索关键词，按选择加载来源说明和本机制作配方，移除首屏不需要的内嵌素材与重复信息。原完整目录接口兼容保留。
- 同类公网 gzip 请求实测，目录从 284237 bytes 降为 112700 bytes；当时解压后的目录约 506631 bytes，仍覆盖全部 958 个模板。这是一次网络采样，不是延迟保证。
- 公开目录在本机持久缓存，再次进入先显示缓存，后台校正新模板、下架模板和版本。缓存有有效期，不把私有账号信息写入公开缓存。
- 预览按模板版本和编码版本保存到受预算限制的本机文件缓存；文件缺失自动重取。回收文件时同时失效内存路径，避免浏览多页后返回旧页面出现空图。
- 下载并发仍为 4，优先当前页；相邻预取从三页改为下一页。首页首批加载时暂停启动新的抠图预热，完成后恢复原空闲调度。

## 首页 GIF

原接口主动取第 0 帧并编码 PNG/JPEG，因此前端即使显示 GIF 徽标也无法播放。现在内置 GIF、声明式逐帧模板和旧动画配方都走公共预览编码器。

保留完整循环与累计时长，最多取 32 个代表帧；超过帧数预算时合并被采样帧的时长。最长边不超过 192，不放大小原图；重动图进一步降到 128 或 96 像素和更小调色板。较小且合适的原 GIF 直接复用。静态预览输出 JPEG。

服务器按模板版本和编码版本缓存公开预览，避免反复渲染；当前版本 `motion-192-v4`。版本匹配的 URL 带公开长期缓存。服务器缓存预算约 128 MiB / 2048 项，定期回收；小程序文件索引最多约 48 项 / 8 MiB，当前可见模板受保护。

实测揉脸猫预览为 14 帧、1400 ms、62633 bytes；摸头预览为 5 帧、约 28 KB。较重样本从约 407 KB 降为 72165 bytes，并保留动画。小程序使用 `.gif` 本机路径，微信生产构建验收读取到 `GIF89a`，并保留了实际界面截图。

## 搜索与新增模板

每个公共模板的搜索词由名称、原关键词、完整默认文案、明确场景词和来源分类补充，新增问候、感谢、睡觉、开心、道歉、鼓励等常用同义词。对“不开心”“笑不出来”“不喜欢”处理否定，避免自动扩为开心或喜欢。新发布模板将搜索词写入元数据；历史模板的目录和详情动态补全。客户端仍支持本地多词交集、分类和分页，不为每次搜索发请求。

新增 12 个可编辑整句文字的日常场景：开心、晚安、你好、谢谢、早安、再见、收到、抱歉、加油、比心、吃饭和打工。它们是文字模板，不进入照片推荐池。素材固定使用 OpenMoji 15.1.0，遵循 CC BY-SA 4.0，保存具体图标链接、署名和变更说明；见根目录 NOTICE。构建脚本是 `tools/collect/build_common_scenes.py`，默认、短替换、两行和空文案均实际渲染复核。
