## 示例分享

详情按钮“分享这张示例”不依赖填写照片或文字。列表继续只请求小缩略图；用户点击后才下载完整示例。`GET /memes/{key}/example` 统一覆盖原生模板和声明式模板，使用与缩略图相同的来源，不重新合成用户输入。声明式 GIF 返回完整帧与时序，原生模板优先返回自身 example 文件，无文件时生成其默认示例。下架、归档或被屏蔽的模板不可凭运行时旧注册记录继续取示例。

私有模板继续使用认证的私有预览路径。客户端校验文件大小及 GIF/PNG/JPEG 头，复制为明确扩展名，再调用既有微信原图分享入口；失败、取消、切换账号和关闭详情均有独立处理。最新示例在有界文件缓存中受保护，避免把“菜单调用成功”当成“对方已收到图片”后过早删除。此前示例可按现有缓存限额清理，不给普通作品或原图转移所有权。

## 卡顿分析与处理

从代码定位到的高风险触发路径：

- `App.onShow → startIdleMaintenance → 1500ms → warmLocalBackground → wx.createInferenceSession`。即使 Promise 包装和定时延后，创建会话仍可能同步编译；旧路径还会尝试 NPU 与 CPU，两者都可能使界面和 GIF 停顿。编辑中 150ms 的 Promise 超时也不能中断同步原生编译。
- 选人时的 `wx.initFaceDetect` 同样会初始化原生引擎；仅用超时竞赛不能证明其不会阻塞。
- 约 622 KB 的 994 项目录使用同步存储，目录映射、关键词标准化和缓存索引反复同步跨桥；图片上传和 alpha 裁切有整幅像素循环。视频 GIF 原先逐帧重新量化且每四帧才让出执行时间。

处理方式：微信端不再创建这两个原生模型引擎，不再下载本机 U2NetP；抠图使用自有服务器已预热的模型，透明图片继续本机复用。自动候选框异步返回，用户可以立即手动调整。框选不启动额外推理或照片上传，只复用同一次识别返回的 mask。新的抠图操作需要联网，这是行为变化。

目录按 32 项分批建立非响应式搜索索引，一次替换可见元数据；新一轮响应会取消旧批次，搜索复用标准化结果。大目录及文件索引异步存储并串行合并索引写入。清理延后到 10 秒空闲，读取作品引用使用异步存储并在操作期间重新核查文件保护；不会扫描删除整个匿名临时池。

图片扫描按 32,768 像素、alpha 裁切按 32 行分批让出执行时间。视频 GIF 每次压缩只对最多 8 个 32×32 帧样本建立共享调色板，每一帧之间让出执行时间；超过 400 万像素的本机视频帧交给现有后台回退。Live 原图的视频标记扫描按 256 KiB 分批进行。既有服务端优先拼图路径继续保留。

这些是消除已知主线程阻塞路径的代码修改，尚不能宣称“所有手机、所有环节零卡顿”。弱网会影响异步操作的等待时间；透明图、手动框选、旋转和翻转仍可本机使用，原图不会因失败替换。
