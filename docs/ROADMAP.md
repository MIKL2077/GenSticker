# 整改优先级与后续工作

本轮实现与复测见 [整改报告](testing/REMEDIATION_2026-10-20.md)。初始测试报告保留历史结论，不作为当前完成状态。

## P0：仍阻断公开上线

- 从可信系统恢复目标环境，完成高权限历史事件处置与全部相关外部凭据轮换。现有主机降权、访问控制和健康检查不能替代可信重建。
- 在新环境验证恢复数据、源码与依赖来源、模型哈希及其他同机业务；明确重建回退窗口。

图片解析整改已实现并复测：Pillow 12.3、允许格式、受限像素与帧预算、兼容 pil-utils 包；294 个启用模板在 Linux 全部生成成功。

## P1：代码已补齐，平台和运维仍需验收

已实现账号存储与上传预算、全局磁盘／文件数量保护、删除／撤回／注销、举报／本机下架、响应流量预算和本地定时监测。部署示例使用共同两核／4 GiB slice；共享环境的三个业务采用独立低权限账号。

仍需：真实运营者隐私政策和联系人、微信平台配置与正向内容检查、iOS／Android 真机、真实云账期及之前已用流量、云控制台费用告警和接收渠道、定期离机加密备份与到期删除。现有监测只写私有状态和 journal，没有对外通知。

## P2：体验修复已实现，扩大效果样本

- 七个名字模板的必填契约与提示已修正。
- 原版之外可保存微信适配版，长边 240 px、500 KiB；实际微信添加入口仍需真机验收。
- OCR 可生成待校对的私有草稿，经预览确认才申请内容检查；识别失败退回当天成功额度，保留独立短时尝试限制。
- 视频增加均衡／更流畅／更清晰选项，提示优先选择 3～6 秒；9 秒上限保留，不承诺所有输入能保持原画质／帧率。
- 公网链路等待仍需不同运营商、弱网和真机测量，不能用源站短时健康测试推断用户端速度。
