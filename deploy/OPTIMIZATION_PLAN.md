# 交互、性能与模板质量优化

2026-10-14；逐步实现，每一步独立提交到 `codex/restore-wechat-final`。

1. **图片报错**：当前 uni-app 微信运行时在生产构建中预加载 `shadow-grey.png`，拼接结果成为 `https/<encoded>/img/...` 相对地址。项目所有页面使用自定义导航，不需要原生导航阴影；构建时只移除该框架预加载，不影响业务图片预加载。
2. **导航和详情**：首页 / 我的之间加入独立圆形 AI 入口，进入已有照片推荐页；来源移至详情底部的小字，完整许可仍保留；收藏按钮移至左上角。
3. **翻页**：一次请求取得精简模板卡片元数据，首页马上呈现名称；预取相邻两页缩略图，前台请求优先，后台预取不设置全局加载状态。缓存有数量 / 字节上限，避免把全部图片和详情塞进小程序桥。
4. **热度**：区分点击、有效收藏、成功生成、AI 曝光与选择，使用匿名安装标识或账户去重并限制事件频率；服务器生成成功计数，AI 结果按 job + slot 去重。热度参考近七日、时间衰减及转化率，首页展示热门前三与热榜 / 探索切换，新模板保留探索机会。无历史数据时明确冷启动，不伪造热度。
5. **端侧生成**：原有 Python / Skia / GIF 代码不能直接在微信 JS 中执行。下发受限 JSON 模板和静态素材，由已打包 Canvas 渲染器处理兼容的静态模板；不下载执行任意代码。优先验证无分割要求、无复杂文本的模板，失败自动回服务端；单任务、像素 / 素材 / 缓存上限、释放画布。Python 模板继续用服务端，并预处理所选照片、缓存纯公开输出、记录耗时定位瓶颈。
6. **动效**：圆形入口呼吸光环、卡片轻入场、点击反馈、弹层与进度过渡，避免持续大范围动画和动态 Base64。
7. **素材来源**：调研 ChineseBQB、爱给、闪萌，按具体素材授权接入；站点可访问或有代码许可不等于所有图片可改编再分发。许可未明确的来源先登记候选而非直接发布；不绕过登录、反爬或付费限制。
8. **转换质量**：除 SHA 去重外增加感知哈希、OCR / 槽位结构重复检查；优先有明确反应文字、稳定主体、可保留动作 / 背景的素材。记录意图、固定笑点与可替换区域，要求原样重建与替换后意图保护检查。会因抠走主体表情或姿势丢掉笑点的图片优先转文字槽位，不能可靠恢复则待处理。用成功转换与用户选择反馈优化候选排序，不降低发布门槛。

## 调研依据

- [ChineseBQB](https://github.com/zhaoolee/ChineseBQB/tree/master)：分类丰富，适合作为候选发现来源；package.json 的 ISC 是代码许可，当前未找到逐图片可改编再分发授权，不能将其整体视为已授权素材。
- [爱给官方素材商用说明](https://www.aigei.com/faq/doc/1.html)：需区分版权购买、CC 素材及其具体条件；表情分类页访问失败，当前不直接批量接入。
- [闪萌版权说明](https://weshineapp.com/copyright.html)：含搜索的第三方内容与用户上传内容，不能把搜索结果统一视为平台授权素材；当前采集页访问失败。
- [微信官方 Canvas 示例](https://github.com/wechat-miniprogram/miniprogram-demo/tree/master/miniprogram/packageAPI/pages/page/canvas)：端侧静态合成使用已打包的 Canvas API 实现，需按设备能力回退。

最终验收记录将在实现后补充；以上性能目标不作为已测得的响应时间保证。
