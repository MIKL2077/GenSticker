# 自动模板与九宫格验收

2026年10月14日开发版。开发分支为 `codex/restore-wechat-final`；微信小程序尚未上传发布。

## 本地打开

微信开发者工具打开 `frontend/dist/build/mp-weixin`，AppID 使用项目已配置值。首页点击“照片一键配表情”。若未登录，页面引导至“我的”的微信登录弹窗；填写昵称、主动选择头像后登录，返回新功能页面。

后端地址仍为 `https://www.shangkun.uk/gensticker/api`。真机需在微信平台设置 request、uploadFile、downloadFile 合法域名为 `https://www.shangkun.uk`，并完善选择照片、头像及相册保存的隐私用途说明。开发者工具已经完成模拟器验证，真机相册授权与保存请在验收时测试。

## 九宫格

1. 选择一张普通人像或物体照片，点击生成。页面显示今日剩余次数与处理进度，预览逐张出现。
2. 支持单选、多选、全选、取消全选；保存所选结果到相册。选择和下载不重复扣次。
3. 推荐入口要求登录，每用户每天3次，全站每天100个任务，同用户同时1个任务。次数以北京时间切日；后端独立执行，删除记录或清理客户端缓存不能重置次数。
4. 重试同一提交不重复扣次；服务失败退回次数，原手动模板入口继续使用。上传格式/大小失败不进入模型任务，不扣正式次数。
5. 页面离开暂停轮询，任务仍在后台继续；重新进入可恢复最近任务并浏览历史。历史可删除，这会清理该任务的图片与对应反馈。
6. 可关闭个性化：清空已有反馈与偏好，后续选择只用于当前下载，不再进入推荐学习；仍能正常制作。
7. 结果静态 JPEG；原有手动入口仍支持 GIF。动物/物体或不可靠人脸不强行套用表情标签。多主体照片选最大连通主体；模型不确定时明确保留原图。

原图与处理缓存24小时后按小时清理，结果7天后清理。只保留模板选择/曝光标签最多90天用于排序，不保留人脸身份向量。私人图片下载要求登录且校验任务归属，无公开图片目录。

## 模板入库

已登记原有294个可用模板，新增9个OpenMoji基础表情模板，共303个。每个模板有稳定 UUID、独立版本，已有 key 继续作为兼容别名。通过 `/templates` 可查看来源、许可、分类标签和版本。

`gensticker-ingest.timer` 每6小时加随机延迟执行。采集流程限定来源、预算与字节数，去重，生成声明式图层，再试渲染后发布；低置信度留待处理，不执行模型生成的任意代码。转换 Skill 位于 `skills/meme-to-template/SKILL.md`，执行器为 `meme_generator.features.ingest`。

当前两个来源：OpenMoji 已自动采集发布且重复运行不重复入库；Wikimedia 的已许可 meme 图片适配器已实现，但当前服务器访问超时，会在下一轮重试。OpenMoji 是基础表情素材，不是全网热门榜。不能把这303个模板描述为已覆盖全网最新热门表情包；当前阶段已具备受控来源的采集、转换、版本化和发布能力，复杂遮挡/动画仍不自动发布。

OpenMoji 采用 CC BY-SA 4.0，输出保留作者、来源与许可；模板详情也显示署名。来源调研发现部分“CC0表情包仓库”同时说明图片仍可能侵权，或尚未实际分发图片，未自动接入。官方依据：[OpenMoji 许可](https://github.com/hfg-gmuend/openmoji#license)、[Wikimedia 机器可读许可](https://commons.wikimedia.org/wiki/Commons:Machine-readable_data)。

## 推荐与运行

本地 U2NetP 提取主体，FERPlus 分析已检测人脸的视觉表达；不判断真实心理，不进行身份识别。模板匹配检查输入兼容性，结合表情、比例、个人标签偏好与多样性。同一基础布局最多2张，候选不足时明确显示较少结果，不复制凑数。

每小时更新标签权重，采用时间衰减、平滑位置校正与全选降权。算法为 `tags-position-v2`，属于初版可解释排序，尚未进行大规模效果实验或宣称模型推荐准确率。可见性监听只记录实际显示的缩略图。

独立 worker 运行于 `/opt/gensticker-worker-venv`，原API虚拟环境未升级模型依赖。模型只在CPU运行、预热一次并复用；九个渲染任务最多并行2个。服务有2GB/两核限额，采集任务一核、最多240秒。付费AI始终关闭，成本账本记录0 API金额与本地CPU/字节成本。没有向外部AI发送用户照片。

真实样例验证：模型预热约0.41秒；主体与表情处理约0.52秒；首批九图服务端约6.8秒完成，微信端9个预览加载、全选与反馈成功。worker 当时约504MB内存。以上是单次样例，不是p95或并发压测结论。测试任务额度已退回，验收账户仍有当天完整3次额度。

## 验证与维护

后端6项功能测试覆盖模板版本/DSL边界、登录和任务归属、幂等与并发限制、次数/退款、私有下载、反馈与删除、崩溃恢复、来源白名单与个性化关闭。原5项账户测试及4组前端测试继续使用；微信与H5构建通过。模拟器已验证生成九图，后续优化再次验证新入库模板通过手动入口生成及署名。

数据库：`/var/lib/gensticker/features/features.sqlite3`；私有文件：同目录下 `private/`；模板素材：`template_assets/`；模型：`/var/cache/gensticker/models/`。原账户数据库不变。备份时暂停独立API/worker/ingest服务，复制数据库及WAL/SHM与素材后再启动；勿只复制SQLite主文件。

观察 `journalctl -u gensticker-worker` 与 `journalctl -u gensticker-ingest`。采集失败不阻断用户生成。已验证网站、Tunnel和API正常；未改动其他项目源代码。升级前API/Nginx备份在 `/opt/gensticker/backups/pre-features-20261014/`。

回滚时先停止新增worker与采集timer/service，再恢复备份app.py和Nginx配置并检查/重载。保留features数据库和私有目录用于恢复或按约定清理，不直接删除原账户数据。
