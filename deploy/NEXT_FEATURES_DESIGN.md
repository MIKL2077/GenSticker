# GenSticker 自动模板与九宫格推荐设计

更新日期：2026年10月14日。此文保留原设计，当前开发版已实现受控采集、模板转换、CPU九宫格、服务端配额与反馈排序；实际范围及验收见 FEATURES_ACCEPTANCE.md。付费AI保持关闭。现有模板生成、保存和分享保持原有流程。

## 产品入口与结果

保留首页的分类、模板选择、上传、文字填写、生成、保存与分享。未来增加“照片一键配表情”入口：用户上传照片，看到处理进度，随后逐张出现九宫格缩略图；点选一张或选择全部，再保存或分享。九宫格属于同一次生成任务，选择和下载不重复消耗额度。页面展示剩余次数；额度耗尽仍可使用现有手动模板。

“我的”继续承载账户、历史和收藏。九宫格历史只保留有期限的结果，不永久存储用户原图。用户可以删除上传与结果，并关闭个性化反馈。

## 两条独立流水线

离线流水线：来源适配器 → 热度候选 → 去重与来源核验 → OCR 与版式分析 → 模板转换 Skill → 自动渲染测试 → 分类与索引 → 原子发布。

在线流水线：压缩上传 → 原子预占额度 → 主体提取一次 → 表情与视觉特征一次 → 候选召回与排序 → 九个不同模板并行渲染 → 渐进展示 → 选择反馈 → 周期性更新排序。

在线生成不能等待爬取、模板转换或模型训练。模板转换 Skill 是离线工作流，不是每个用户请求都调用大模型。

## 热门模板来源与身份

“全网热门”实现为可扩展的来源列表，先接入许可明确的公开数据、开放接口、创作者授权合集及用户授权投稿。每个来源需定义获取方式、频率、最大字节数、热度字段和许可；没有访问权限或不能证明可再分发的图片不自动发布。站点不同，热度先按来源归一化，再结合时间衰减；不可把下载量等同真实热度。

建议初始每六小时采集一次，每天发布一批合格模板，每日最多下载100个候选、转换20个。以上是可调建议值，并未创建定时任务。使用 ETag/Last-Modified，禁止无限分页；单图2MB、单批200MB上限，并设置月度采集字节预算。任务错峰运行，避免与用户渲染及 OpenClaw 抢资源。

新增模板使用稳定 UUID `template_id`，现有 `key` 保留为兼容别名。模板的每次修改递增 `version`；反馈与生成记录保存二者，不能因改名、排序或删除重用 ID。保存来源 URL、作者、许可、采集时间、原图 SHA-256、感知哈希和发布时间。完全重复合并，近似图聚类但不直接误删。

沿用仅文字、仅图片、图文混合分类，增加多维标签：情绪、场景、主体类型、静态/动图、可用图片数量、文字槽位、热度和适配规则。标签可以多选，分类计数仍按原有输入要求计算。

## 模板转换 Skill 的合同

拟建离线 Skill `meme-to-template`，输入为授权图片、OCR 框、来源与许可；输出是经过 JSON Schema 验证的声明式模板及素材，不能直接运行模型生成的任意 Python。

模板描述包括画布尺寸、背景图层、主体槽位与裁切/缩放/遮罩/旋转、文字框/字体/描边/换行、动图帧与时长、输入约束、默认文案、分类标签、适用主体、模型/提示词版本、素材哈希和渲染引擎版本。统一引擎用 Pillow/现有 meme-generator 绘制。受支持的操作白名单相当于用代码一键生成，而不会让爬来的文字或模型输出获得服务器执行权限。

优先覆盖文字叠加、单主体替换、双主体和简单动画。原图中遮挡严重、主体与背景无法分离、依赖复杂重绘的图片不承诺自动复原。自动识别低置信度或测试失败后进入待处理区，保持采集流水线继续运行；只发布通过测试的模板。因此“全自动”指合格模板自动入库，不代表所有网络图片都能无损转换。

转换采用本地 OCR、图层规则和现有模板近似匹配优先；只有无法确定槽位时才考虑视觉模型描述版式。每个候选限制最大模型调用次数及 token 数，禁止无上限自我修复。模型输出、图片内文字与网页内容均当作数据。

自动测试涵盖空输入、最小/最大输入、中文长文本、透明图、横竖比例、边界裁切、字体溢出、动画帧数、耗时、内存、结果类型和九宫格适配。重建示例做感知相似度与布局检查，但相似度不是许可或质量保证。发布时事务切换版本，失败回滚到旧版本。

## 主体提取与表达匹配

上传前缩小 JPEG，后端纠正 EXIF、校验格式、限制像素和动画帧数、清除元数据；原图只进入私有短期空间。抠图用 CPU 上的轻量 ONNX 模型，单张图只运行一次，透明主体与视觉特征在同一任务中复用。多人时选择最大主体；主体不明确或置信度低时保留原图裁切，并提供用户选择/调整的后续扩展，不把失败伪装为成功。

先判别人、动物、物体，再做适用的表达匹配。人脸表情模型只产生“笑脸、惊讶、平静”等视觉标签和置信度，不能推断用户真实心理。非人主体、无人脸、低置信度使用视觉风格、构图和通用模板，不能套用人脸模型。避免为本产品建立人脸身份识别库。

召回候选先检查模板输入兼容性，再结合情绪标签、场景标签、视觉特征相似度和热度；排序加入个人偏好并进行去重、多样性约束。初始建议九个位置中六个偏匹配、两个多样化、一个探索；数量只是实验配置。候选不足时减少结果并解释，不能通过复制凑满九张。文字型模板使用经审核的默认文案，不在用户链路依赖实时大模型写文案。

## 免费优先与资源边界

首选本地处理：Pillow 合成、PaddleOCR 离线 OCR、rembg 的 CPU 接口加许可合适的轻量模型，以及可选本地视觉特征模型。没有第三方按调用计费，但占用服务器 CPU、内存和带宽，仍需限额。rembg 软件的 MIT 许可不覆盖所有模型权重，部署前必须逐一确认模型许可。[rembg 官方项目](https://github.com/danielgatis/rembg)、[PaddleOCR 官方项目](https://github.com/PaddlePaddle/PaddleOCR)。

DeepFace 可作为人脸表情分析候选，但框架及所选模型的许可、大小、CPU 延迟需分别评估；不启用年龄、种族或身份分析。[DeepFace 官方项目](https://github.com/serengil/deepface)。BRIA RMBG-2.0 的公开权重是非商业许可，不能直接作为上线免费商用方案。[模型官方说明](https://huggingface.co/briaai/RMBG-2.0)。

免费云端视觉 API 只能作为离线模板转换的可选适配器。Gemini 的部分模型有免费层，但存在地区、速率、数据使用和模型差异；不能把它作为当前国内服务器或用户照片的默认依赖。免费层内容的数据使用条款需要特别核对，不发送未经明确同意的用户照片。其他国内供应商按上线时实际官方免费额度和隐私条款评估，试用赠金不当作永久免费。[官方价格](https://ai.google.dev/gemini-api/docs/pricing)、[官方可用区域](https://ai.google.dev/gemini-api/docs/available-regions)。

默认 `paid_ai_enabled=false`、每日付费预算0。免费额度不足、网络失败或达到预算时使用本地规则降级，不能自动切换收费模型。后续启用付费模型需明确预算和供应商配置，账本按调用记录 token、金额与任务，但不记录密钥和照片内容。

现有4核16GB且共享网站与OpenClaw：先使用一个预热推理进程、一个模型会话，ONNX线程限制2，用户任务优先，离线采集/转换低优先级，禁止一口气启动九个重模型。先测量实际余量再设置内存限额，建议试验新增工作进程上限2GB；现有生成服务仍保留隔离。不要默认下载大视觉语言模型到这台共享服务器。

## 快速响应、任务与缓存

接口快速返回202与任务ID，不保持一条HTTP请求直到九张大图完成。客户端用1秒起步、逐渐增加间隔的状态轮询，页面隐藏停止轮询，回来继续；首张准备好即可显示，九张生成尽量并行但渲染并发最多2。低清预览优先，用户选定后下载完整图，九宫格页面只存文件路径。

将抠图模型预热、模板素材预载、缩略图静态化、特征离线构建。缓存键包含用户范围、图片哈希、模板版本、处理模型版本与参数；不同用户不得共享私人照片结果。命中缓存不再调用模型，但仍受访问限速。图片过期后删除，禁止用公开可枚举URL访问私人结果。

初始体验目标：任务创建p95小于500ms（不含上传）；首张预览p95小于5秒，全部九张p95小于12秒；暖机命中更快。这些是待压测目标，不是已测结果。CPU抠图、8Mbps带宽及共享业务可能达不到；先以50张授权测试集测冷/暖启动、人物/动物/物体、不同尺寸、并发1/2/4。预览控制在每张约30–60KB，原图与大图仅按需传输，避免9张GIF默认下载导致流量增长。

## 次数、费用与防刷

需要模型的新入口要求微信登录，以服务器验证的用户ID计数，不能信任前端传来的 openid 或次数。建议初期每日每用户3次九宫格，每次1张输入、最多9张结果、同用户同时1个任务；手动生成另设较宽的频率限制。午夜按 Asia/Shanghai 切日，并设置全站任务预算，初始建议每日100个模型任务，压测后调整。

用事务预占次数，成功后确认，服务故障退回；同一幂等键重试不多扣。账本区分reserved/consumed/refunded，设置预占过期回收，崩溃也能恢复。拒绝非法图片不调用AI、不占正式次数，但计入防刷频率。组合用户/IP/设备信号限速，IP单独作为弱信号，避免共享网络误伤；用户删除客户端缓存不能重置次数。

付费预算须在发出调用前原子预占最坏金额并限制输出，完成后结算；额度与付费预算都必须在服务端执行。总开销分别记录AI金额、推理CPU时间、缓存字节和带宽，不能用“免费API”忽略服务器流量成本。

## 反馈与周期优化

记录推荐曝光九张、位置、模板ID/版本、算法版本、选择、全选、下载、重新生成及是否完成展示。仅曝光但未选择不直接等同不喜欢；选全部和一次下载九张不能算九个独立强偏好。事件ID幂等去重，客户端事件必须验证属于该用户的任务。

第一阶段使用标签偏好和可解释加权排序。每天更新用户标签分布与模板整体选择率，加入位置偏差修正和时间衰减；新用户使用热门与多样化冷启动。反馈达到足够样本后才考虑轻量学习排序/上下文探索策略，不在线训练大模型。保留算法版本与对照组，观察至少选择率、再生成率、多样性、延迟、失败率和每任务成本。

推荐日志不保留人脸图或生物特征，尽量只保留模板标签、结果选择与粗粒度置信度。私人原图建议24小时清理，结果建议7天清理；反馈保留期限建议90天，最终以发布的隐私政策为准。用户关闭个性化后用非个人排序，删除账户时清理个人偏好及对应上传。

## 建议接口与数据

新增接口草案：`GET /recommend/quota`、`POST /recommend/jobs`（幂等键、图片资产ID）、`GET /recommend/jobs/{id}`、`GET /recommend/jobs/{id}/results/{slot}`、`POST /recommend/jobs/{id}/selections`、`DELETE /recommend/jobs/{id}`。资产先通过受限上传创建；状态、下载和反馈都要求认证并检查任务归属。

新增数据实体：templates、template_versions、sources、ingest_candidates、conversion_runs、upload_assets、recommend_jobs、job_results、recommend_exposures、selection_events、user_preferences、quota_ledger、cost_ledger。当前少量访问可先用独立SQLite WAL与持久化任务表，任务有租约、重试次数和恢复状态；流量与并发增长后迁移PostgreSQL/Redis，不能只靠内存队列。

## 实施顺序与验收

1. 模板ID/版本映射、标签、声明式渲染与离线测试；现有294模板全部仍能生成。
2. 一个许可明确的来源与转换Skill；重复采集幂等、失败隔离、自动发布回滚、资源预算验证。
3. 单图抠图与基础召回九宫格；人物/动物/物体退化策略、私有资产归属、任务恢复验证。
4. 服务端次数和成本账本、渐进展示与缓存；重复重试只扣一次、故障退款、超额无模型调用。
5. 选择反馈与离线偏好更新；事件去重、关闭个性化、版本回滚和对照实验。

每阶段独立提交到现有GitHub开发分支，验收后再部署。用户已授权开发，受控采集与本地CPU模型已部署；付费API仍未启用。更广来源与复杂动画转换继续受许可、质量及资源限制。
