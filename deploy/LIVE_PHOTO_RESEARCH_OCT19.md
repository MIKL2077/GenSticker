# Live Photo 读取与小程序本机 GIF：本轮调研

核查日期：2026-10-19。目标是在微信小程序中，从相册选取原始动态照片，再在本机完成编辑与 GIF 编码。本轮不使用快捷指令，也没有引入另一套需要用户安装的转换应用。

## 用户提供文章的适用范围

[《uniapp小程序 LivePhoto(实况图片)实现详解》](https://juejin.cn/post/7542488844399083555) 的组件接收 `src` 和 `videoSrc` 两份已经存在的素材，控制长按时的视频播放、暂停与封面切换。它展示了 Live 的播放交互，没有取得 iPhone 相册配对视频的代码，也没有将缺少配对视频的静态照片恢复成动态。

因此可以借鉴播放交互，但不能由文章中的组件推导出“相册直接选择 Live 即能取得 MOV”。本轮在编辑页面加入了实际视频播放和可拖动的进度条，显示后续画面。

## 先区分取资源和转 GIF

取得视频资源后，本机转换已经可行：微信的 VideoDecoder 解码、离屏 Canvas 裁剪/叠字、gifenc 编码。已有 9 秒路径，本轮进一步支持自由字幕位置与格式；不兼容的设备自动走压缩视频＋后台队列。

原始动态资源是否被微信交给小程序，是另一项前提。编码器、播放器或云端 FFmpeg 都不能重建未取得的原始时间帧。

### iPhone 相册中的 Live

Apple 的 [PHAssetResourceType.pairedVideo](https://developer.apple.com/documentation/photos/phassetresourcetype/pairedvideo) 明确提供 Live 的原始视频资源。原生 iOS 应用可以通过 PhotoKit 获得这一资源；它不是小程序 JavaScript 可以直接调用的系统接口。

本轮重新读取了[微信官方 API 类型定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)：`chooseMedia` 的公开文件类型为 image/video/mix，MediaFile 提供单个临时文件路径、视频缩略图、宽高和时长；没有 Live 资产标识或配对 MOV 读取字段。`sizeType: ['original']` 用于请求原始文件，不能据此保证客户端同时提供配对视频。

结合目前真机只返回静态照片的结果，工程结论是：**没有找到当前可依赖的公开 API，能保证在该微信客户端中无感取得 iPhone Live 的配对视频。**这不是声称未来所有微信版本永远无法提供。若客户端实际返回了视频，本项目会沿现有视频路径自动识别；目前不能把未提供的系统资源当作已支持功能交付。

### 带内嵌视频的动态原图

[Android Motion Photo 格式规范](https://developer.android.com/media/platform/motion-photo-format) 定义了图片与视频拼接的文件容器；规范也提醒，保留了 MotionPhoto 元数据并不意味着视频字节仍存在，必须实际确认视频内容。

项目相册选择请求保留原始文件。本机扫描实际 MP4/MOV 容器数据，找到后提取至本机临时视频，进入同一编辑与编码路径。没有视频字节则明确说明原因，不把封面做成伪动态。JPEG/HEIC 被微信或其他软件重新编码、只保留静态部分时，此方法同样无法恢复已丢失的视频。

本轮以真实 JPEG＋MP4 拼接容器进行前端验证：本机提取后生成 3 秒、30 帧、135×240 的 GIF，163041 bytes；未上传源文件。该验证覆盖文件格式与本地编码，不替代具体 Android 品牌、相册或微信版本的真机兼容性测试。

### WebView、LivePhotosKit 与原生插件

WebView 或 LivePhotosKit 可消费已经取得的视频资源；它们不会自动为小程序开放 PhotoKit 的资源读取能力。原生 iOS/uni-app App 插件可以在原生应用内访问配对资源，但不能作为微信小程序前端插件直接执行。因此本轮未添加一个看似能选 Live、实际上仍要求额外转存的入口。

## 本轮交付与限制

- 完全移除快捷指令页面、配对口令、接收路由、签名生成器及相关活动测试/部署脚本；生产侧撤销旧口令表，旧地址返回 410，删除公开教程。历史验收报告保留并标记为已被替代。
- 保留相册动态原图的实际视频提取和本机 GIF 编码；iPhone 仅返回静态封面时，在选图前后都给出准确说明。
- 视频编辑可播放、拖动定位；文字可移动并调整颜色、大小、粗细、背景。本机与后台使用同一归一化字幕参数。
- 正常等待显示成品；收起等待弹层则继续在生成队列中制作。用户离开编辑页面不会取消已经开始的本地任务；小程序进入系统后台时，仍受微信运行调度影响，不能承诺被系统终止后本机 CPU 继续运行。后台 worker 已接受的任务独立于页面。

真正的 iPhone 单次选图全自动 Live 读取，需要微信客户端交付视频资源，或在支持 PhotoKit 的原生应用中实现。这一边界已在页面中如实表达，没有使用“已无感支持”的文案。
