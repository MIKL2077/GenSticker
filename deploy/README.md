# GenSticker 部署入口

目标是微信小程序。当前部署方式、资源预算、加密备份和回滚详见 [运维说明](../docs/OPERATIONS.md)；功能见 [README](../README.md)，完成状态见 [整改报告](../docs/testing/REMEDIATION_2026-10-20.md)。

运行代码与 API／worker 虚拟环境放在同一 release 目录，通过 `/opt/gensticker-current` 原子切换。`meme-generator` 与仓库内 `pil-utils` 保持相邻。状态和模型与 release 分开，服务账号无登录 shell。环境文件私有；不可把真实凭据放入这些示例。

本目录的 unit、slice、timer、Nginx 和限额文件是部署参考，必须先核对目标机器。`stage-runtime.sh` 准备候选环境，不会自动切换线上业务。历史 `apply-*` 脚本保留供追溯，不能作为当前一键部署入口。

```sh
cd frontend
npm ci
npm run build:mp-weixin
npm run check:mp-weixin-package
```

用微信开发者工具导入 `dist/build/mp-weixin`，保持域名校验开启，配置真实合法 HTTPS 域名。真机、隐私授权和微信审核需分别验收。

微信上传压缩和组件按需注入由 `frontend/src/manifest.json` 固定配置。生产构建会无损重压缩输出目录的 PNG，保留像素、透明度和元数据，不修改源图片；图片与音频总量超过 200 KiB 或当前整包超过 1.5 MiB 时构建失败。`check:mp-weixin-package` 可单独检查已有构建。使用已经导入的旧工程时，通过 `frontend/scripts/sync-weixin.cjs` 同步最新构建后，在微信工具中重新扫描代码质量；留意本机 `project.private.config.json` 是否覆盖了压缩设置。不要只修改 `dist/` 内的生成文件。

队列“重新编辑”需同步更新前后端：新增 `GET /studio/jobs/{id}/edit` 和 `GET /studio/live/assets/{id}/source`，校验登录、素材归属与原有七天保留期，只恢复编辑内容，不创建制作任务。无数据库迁移；没有保留原始制作素材的旧任务不能恢复。引导中的真实示例随小程序打包，不依赖这些接口。

2026-10-23 已补齐线上这两个接口，修复新版前端点击“重新编辑”返回 404 的问题。仅更新两个后端模块并重启 API；复用原先再次制作所保留的素材，不增加副本或延长保留期。上线前备份代码及数据库，健康检查失败自动恢复代码；验证恢复原照片、文字、视频编辑参数、跨账号拒绝访问及恢复时不创建任务。前端恢复失败提示改为弹窗，避免被成品预览遮住。

同日补齐一键生成结果的 `GET /recommend/jobs/{id}/results/{slot}/edit`：按任务与结果序号恢复原模板、默认文字和 worker 已缓存的主体图。主体仍按原有 24 小时期限清理，不新增服务器素材副本；原素材过期、模板下架或版本变化时明确拒绝恢复。已同步上线该接口。多选分享展示全部所选结果，支持切换原图、整组保存及本机静态拼图；微信原图分享仍按单图调用，动图不会被静态拼图替换。选图优先使用 `chooseMedia`，旧版回退 `chooseImage`，选图前不启动抠图模型或解码照片。

客户端缓存管理独立于 `/account/storage` 返回的服务器素材用量。客户端在空闲时清理过期自有文件，按预算保留可重取素材；写文件、导出画布和下载遇到空间限制时，会回收可重取缓存并自动重试。原图、活跃编辑及有效本机队列素材受到保护，缓存回收会同步失效对应索引，避免再次命中已删路径。恢复成功保持静默；恢复失败时保留原图并返回操作失败。模型预热改为进入小程序后空闲 1.5 秒启动，选图、主体编辑、生成期间暂停新的预热步骤，应用隐藏时暂停调度；模型文件和 NPU／CPU 回退逻辑保持校验。

等待弹窗用 600 ms 内两次点击收起到队列；第一次点击显示再次点击的提示，成品预览仍可单击关闭。完成卡片跨页面显示共 5 秒（前 4.2 秒突出显示，后 0.8 秒淡出），点击可直接打开对应成品；任务与图片通过账号绑定的内存交接传递。单图分享说明明确默认首张勾选，预览中可切换当前图片。新增模拟存储不足、空闲预热、通知时序、账号隔离及双击回归；微信工具验证了真实生成、查看成品和淡出。真机磁盘压力与 NPU 首次加载仍需设备复测。

共享主机上的应用加固不能替代历史高权限事件后的可信重建和服务商侧密钥轮换。实际主机、事件记录、备份与访问资料通过私下渠道交接，不放入公开仓库。

模板自动维护流程见 [采集、归档与试用卡片验收说明](../docs/testing/AUTOMATED_LIBRARY_2026-10-23.md)；当前上线状态见 [2026-10-26 自动发布与分享封面验收](../docs/testing/AUTO_PUBLICATION_2026-10-26.md)。`gensticker-ingest.timer` 每六小时运行来源发现、MiniMax skill 拆解、真实图片复核，默认目标五个、范围三至十个。达到配置目标记 completed；仅部分合格记 partial，仅发布合格项；零个合格记 attention，不能用不合格模板补数。同一时段的终态报告不会因重复启动而重做，显式重试用 `--force`。订阅凭据单独保存在 root 私有环境文件，环境示例不包含密钥；开启自动发布前必须检查同源模板对照图。`package-scheduled-library.py` 与 `apply-scheduled-library.py` 支持当前运行版本的文件哈希校验、无活跃制作任务时更新及健康检查回滚，不会自动开启新定时任务。

2026-10-26 已通过真实模板验收并在现有服务器私有配置中启用 `GENSTICKER_MINIMAX_ENABLED=1`，不需要人工逐张点击发布。不合格项仍留待处理。发布入口会再次验证完整主审核记录、当前 skill 哈希、源图输入契约、每帧每个人脸槽的本地覆盖证据、逐帧 VLM 复核和素材哈希；审核记录随模板版本保存。新环境的示例开关保留 0，避免未经验收直接上线。

分享封面通过公开、无登录要求的 `GET /share/cover-v2.jpg` 提供，部署包包含 `meme_generator/assets/share/cover-v2.jpg`。它是 logo 衍生的三张表情插画，600×480 JPEG，版本化 URL 可公开缓存一年，不增加小程序媒体包体。首页默认分享及其他六个页面使用该封面；明确分享已生成图片时沿用该图片。分享个人页／队列等页面时链接指向公开首页，不带账号或任务信息。后续换图应递增 URL 版本，避免缓存旧封面。

2026-10-27 新增 `cover-v3.jpg`、`cover-v4.jpg`、`cover-v5.jpg`，与 v2 组成四张封面池。每次分享回调随机选择一张，同一次小程序会话内避免连续两次相同；明确分享成品图片时沿用成品。后端 `features/share.py` 仅允许四个公开文件名，保留一年公开缓存和旧 v2 地址。打包脚本包含分享路由及全部版本化封面；更新前端后需重新上传小程序，服务器封面部署完成后立即可用。原始生成提示词见 [封面素材说明](../backend/meme-generator/meme_generator/assets/share/README.md)。

七个页面必须直接调用 `onShareAppMessage` 注册分享回调：当前固定版本的 uni-app 编译器不会从间接调用的 composable 中推导页面所需的原生分享方法。构建时页面产物应带分享 runtime hook，微信原生页面上应存在可调用的 `onShareAppMessage`。只检查 Vue 初始化成功或单测 composable 回调并不能验收右上角分享菜单。

`gensticker-archive.timer` 每月一日统计并归档公共模板，线上发布数量硬上限 8000。当前归档目标是项目仓库的独立 `template-archive` 分支；先推送并重新拉取验证，才释放未共享的本地素材。通过 `sudo gensticker-template-admin report/list/restore` 查看报告与恢复模板。日志策略安装器 `apply-log-policy.py` 限制 journal 和文本日志轮转并设置新 Docker 容器的默认日志预算，不重建已有容器。
