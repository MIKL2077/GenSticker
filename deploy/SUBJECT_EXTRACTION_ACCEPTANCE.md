# 可选主体提取与多样本 Skill 验收

> 本页记录旧版生成前开关；当前图片上传后即可编辑和预览去背景结果，见 [图片编辑验收](IMAGE_EDITOR_ACCEPTANCE.md)。

2026-10-14，分支 `codex/restore-wechat-final`。后端已部署，公开健康检查返回 295 个模板。“笑不出来”保持原 key / UUID，升级 v3，仍需一张上传图片及一条可编辑文字。

## 使用路径

打开图片模板详情 → 选择是否“提取图片主体”（默认关闭）→ 上传图片，可选“裁剪区域” → 生成。关闭时直接用图像槽位合成；开启时由服务器本地 U2NetP 提取最大主体后合成。透明输入复用 alpha；不要求正面人脸，不进行身份识别，不调用外部照片 API。提取的是前景，不能自动决定前景中的哪部分是头像，帽子、衣服等需要用户裁剪输入区域。

模板旧头部清除及背景修补在制作 / 种子恢复阶段完成，用户生成阶段不再定位或清除模板主体。预览另用参考素材保留原狗头。新模板不依赖原来的 Haar 人脸检测、眼部对齐或 GrabCut。复杂图层仍在服务端合成，两个原有兼容模板继续支持本机 Canvas。

提取在现有两个生成并发槽内执行；手动入口只初始化主体模型，不载入表情分类模型。私有主体内存缓存最多 8 项 / 8 MB / 120 秒，按访问身份与照片哈希隔离。生成缓存包含提取开关，响应禁止公共缓存。动画、空透明图片、过大输入或提取失败有明确提示，用户可保留输入并关闭提取重试。

## 验证结果

- 本地和服务器 25 项功能测试通过，服务器 5 项账户测试通过。覆盖可选提取、透明图不调用模型、普通图单次分割且不加载表情模型、动画 / 空图错误、无需正面人脸、固定区域、同 key v1 → v3 升级、账户隔离及原有任务和缓存流程。
- 六组前端测试通过，微信小程序和 H5 构建通过。微信模拟器验证开关事件与父页面状态一致、默认关闭、上传并生成成功。开启一次约 5.01 秒；关闭并使用裁剪照片一次约 2.68 秒。两次包含网络与首次准备，输入不同，均是单次功能观测。
- 隔离本地真实 HTTP 样例：直接生成约 17 ms，开启提取约 274 ms，同请求缓存命中约 4 ms；隔离服务器直接渲染约 44 ms、提取加渲染约 630 ms。不同环境 / 样例，不能当作线上响应保证或并发压测结果。
- 公开 `/healthz` 返回 `status=ok, templates=295`，模板信息返回 version 3、min_images 1、新输入提示。GenSticker API、worker、Nginx、Cloudflare Tunnel 均 active。
- 裁剪能力使用微信 `cropImage`，不支持的平台保留相册裁剪提示。真机相册权限、裁剪界面与保存仍需扫码验收；模拟器成功不替代真机验收。

## Skill 回归与边界

新增三份不含图片的 brief 与私有回归 runner：猫咪双行文字、Doge 分散文字、农夫帽子下的脸部槽位。来源、许可、关键固定区域、失败原因和复现命令见 [多样本记录](../skills/meme-to-template/references/multi-sample-tests.md)。这些样本渲染跑通但未发布：猫咪纹理修补仍有痕迹，农夫输入帽檐冲突需裁剪，Doge 字体近似需验收。低像素误差不等同于视觉质量或保留笑点。

Skill 已增加离线背景准备、可选前景提取、字形遮罩、单行缩放 / 溢出拒绝、水印保护和明确待审核状态，并同步到此前安装的本机目录。测试照片、下载素材和生成截图仅保留私有临时目录，未添加到 GitHub。

## 部署与回退

修改范围为 GenSticker 源码、独立 API 虚拟环境 ONNX Runtime 依赖及其 systemd 模型缓存路径；未重装服务器或修改其他项目。旧源码与服务配置备份在 `/opt/gensticker/backups/pre-subject-choice-20261014/`。回滚需同时恢复源码 / 服务配置与模板旧版本定义，保留账户、历史和模板版本数据；重编译相应前端。旧 v2 的人脸检测行为见历史验收，不代表当前版本。

部署期间 SCP 重复认证使本机管理出口触发 Fail2ban。通过已登录云控制台 WebTerminal 查看日志后，仅解除该来源的误封，防护继续运行；后续使用单次密码认证传输 / 部署。未添加永久白名单、未关闭防护、未重启整台主机。
